# Mail Inbox (gacha-mail across vsservice + VintageAPI + lhgui)

## Destination

Согласованная спецификация системы почтового ящика («gacha-mail») через vsservice + VintageAPI + lhgui: единый inbox, поглощающий выдачу донат-покупок и системные/админ-награды, плюс **kit-builder** (захват содержимого сундука в редактируемый кит с game_code + картинками), питающий разворот кит-покупок в конкретные item-вложения. Итог — спец на хендофф; реализация вне карты.

## Notes

- Домен: Last Hearth (Vintage Story сервер). Repos: `vsservice` (Go, владелец домена `mail` + общий MongoDB), `VintageAPI` (серверный C#-мод, физическая выдача в игру), `lhgui` (клиент C#, UI).
- **Транспорт: зеркалим DailyRewards.** vsservice пишет письма в общий MongoDB; VintageAPI читает Mongo напрямую через backend-сиам `IMailBackend` + `SetBackend`; lhgui — сетевой канал + `ChangeNotifier`, request-on-open + push-снапшот. **NATS не вводим** (out of scope).
- **Вложения — два примитива** (тикет 01): `items` (game_code + qty + attr-снапшот) и `coins`. «Кит» вложением НЕ является — разворачивается в список `items` at-compose. **`kit-ref`/grant-ref отброшены.**
- **Per-player стейт — всегда `mail_claims`** (тикет 01): каждый получатель (targeted/broadcast) = строка `(mail_id, player_id)`; broadcast не спецслучай. Стейт-машина `unread→read→claimed` + терминальные `expired`/`revoked`.
- **Запись писем — только vsservice** (Q7): donate-домен (внутри) + сайт-админ `ComposeMail`. VintageAPI письма НЕ создаёт — только читает Mongo и пишет `mail_claims` при claim (контракт 05). Игровой команды выдачи `/mail give` НЕТ (Q8): все награды/киты выдаются с сайта; pre-wipe «всем кит» = broadcast с сайта. Событийные авто-награды из игры — не в этом эффорте (fog).
- **kit-builder capturekit — не выдача, а создание шаблона.** Игровая команда захвата сундука пишет кит-определение (game_code+attr+картинка) **напрямую в общую Mongo-коллекцию `kits`** (зеркало DailyRewards — игра владелец контента, Mongo-direct). vsservice **читает** `kits` для разворота кита в `items`-вложения at-compose и **пишет только метаданные** (title). Выдача кита — отдельно, broadcast/targeted с сайта.

> ⚠️ **ПОПРАВКА (charting kit-builder, сессия 2): Q7 gRPC/machine-scope для capturekit ОТБРОШЕН.** VintageAPI НЕ держит никакого клиента к vsservice — ни gRPC, ни HTTP, ни JWT, ни OAuth m2m. Вся интеграция VintageAPI↔vsservice = **Mongo-direct** (`VINTAGEAPI_MONGO_URL`, зеркало DailyRewards/ShipTrading/Skin). Капчур пишет кит-определение прямо в Mongo, как DailyRewards пишет claims. «vsservice единственный писатель» был инвариантом **писем-выдач** (риск дублей claim), не кит-**шаблонов**. Иконки предметов рендерятся на клиенте, заливаются в MinIO **VintageAPI-сервером своими creds** (не presigned-JWT, которого в игре нет).
>
> ⚠️ Ключевое разведение (не спутать в след. сессиях):
> - **capturekit** = игра → **Mongo `kits` напрямую** + иконки → MinIO (VintageAPI creds). Создание/обновление **шаблона** кита. Редко, админ. Тикеты 09/10.
> - **compose/broadcast** = сайт → vsservice, **выдача** письма игрокам (включая развёрнутый кит, читаемый из `kits`). Тикет [Админ-compose API](issues/04-admin-compose-api.md), разворот — тикет 11.
> Игра НИКОГДА не выдаёт письма напрямую и не пишет в Mongo письма/claims-выдачи (только кит-определения в `kits`).
- UI: новая секция **Mail** в `GuideScreen` (главное окно сервера) рядом с «Events», бейдж непрочитанных в сайдбаре и HUD.
- Выдача (VintageAPI): `TryGiveItemstack` → fallback `SpawnItemEntity`, снятие `transitionstate`; монеты `$inc` в `donate_wallets`. Идемпотентность как donate `applied_claims` / DailyRewards `ItemsGiven` — claimed-before-grant.
- Каждая сессия консультирует skills: `grilling` + `domain-modeling`; для UI-тикета — `prototype`; при реализации — `add-feature`.
- Планирование, не исполнение: тикеты дают **решения**, не код.

- [Модель письма и proto `mail/v1`](issues/01-mail-model-proto.md): вложения = 2 примитива (`items`+`coins`, kit-ref отброшен, кит разворачивается at-compose); per-player стейт всегда в `mail_claims`; стейт-машина `unread→read→claimed` + терминальные `expired` (не TTL-delete) и `revoked` (отзыв админом непроклейменного).
- [Донат-покупка → письмо](issues/02-donate-purchase-to-mail.md): письмо = 4-й шаг в `Buy()` `seq.Do` после `CreatePurchase` (без NATS); зависимость `donate → mail` через порт `MailComposer` в `donate/usecase` (примитивные типы, mail не импортирует donate → нет цикла); развилка по типу — `type=item` авто-письмо сейчас (`items{item.Code, qty=1}`), `type=kit` остаётся на ручном `MarkIssued` до kit-builder; compose идемпотентен по `purchase_id`; `MarkIssued`/`IssuedAt`/`IssuedBy` deprecated (не удалять), авто-item штампует `IssuedBy="system:mail"`.
- [Админ-compose API](issues/04-admin-compose-api.md): `ComposeMail`+`RevokeMail` — админ-методы того же `MailService`, разделены scope. `ComposeMail`: `recipient` oneof `{user_id|broadcast}`, `repeated Attachment` (тот же примитив из 01/02, только `items`+`coins` — kit не примитив запроса), optional `expires_at`+`idempotency_key`, `sender="admin:{jwt_sub}"`. Валидация только структурная — `game_code` семантика откладывается на at-claim в 05 (`Unavailable`). `RevokeMail(mail_id)`: флаг `revoked` на документе, идемпотентен, `NotFound` если нет письма. Scopes `mail:compose`/`mail:revoke` раздельные; игроцкие = `ScopeAuthenticated`. Роуты `/v1/mail:compose`, `/v1/mail/{id}:revoke`.
- [UI почты в GuideScreen (lhgui)](issues/06-mail-ui-guidescreen.md): раскладка = **вариант B (drill-in)** — список писем на всю ширину плиты → клик в полноэкранный разворот с «‹ Назад» (A split/C grid+modal отброшены; прототип на ветке `research/mail-ui-prototype`, `lhgui/docs/mail-page-prototype.html`). `MailPage` зеркалит `DailyRewardsPage`; строка = `AtlasCard` (unread-точка+жирный title, meta-`Wrap` со статус-`AtlasBadge`/sender/дата/broadcast/⏳expires, attach-`Row` через `ResolveStack`+`ItemStackDisplay`); разворот несёт body(plain `Text`)+attach-panel+Claim-footer; **MarkRead — сайд-эффект drill'а**. Сортировка — на сервере. Пакеты `Mail/MailPackets.cs` (`RequestMail/MailEntry/MailList/MarkRead/ClaimMail/MailActionResult`, enum `MailEntryState`≠`MailStatus`, зеркало `DailyRewardPackets`); `Mail/MailModSystem.cs` (channel `lhgui-mail`, `MailModel:ChangeNotifier` с `Unread`, router+`PlayerNowPlaying` push **без** attendance/NotePlayerVisit, `SetBackend(IMailBackend)` из 05). Интеграция: `MenuSection.Mail`+навитем(бейдж `Unread`, нужен `envelope.svg`)+`BuildContent`-арм+листенер; `GuideModSystem.Open()`+=`MailModSystem.Instance?.RequestState()`. **Отличие от DailyRewards: почта имеет легитимный пустой инбокс** (`EmptyState`), а не «нет секции»; секция скрыта только без бэкенда. **HUD-бейдж — простая сумма** непрочит.почта+незабранные награды (fog «агрегация HUD» graduated → решён здесь: один брасс-бейдж, YAGNI на раздельные). Lang `lhgui:servermenu-section-mail`+`lhgui:mail-*` (en/ru, LangParity).
- [Контракт доставки IMailBackend (VintageAPI)](issues/05-imailbackend-delivery-contract.md): сиам `IMailBackend` = зеркало `IDailyRewardBackend`, 3 метода (`GetMailAsync`→`MailListPacket?` null=скрыть, `MarkReadAsync`, `ClaimAsync`), `ClaimAll` отброшен (клиент циклит `ClaimAsync`). enum `MailStatus{Granted,AlreadyClaimed,Expired,Revoked,Unavailable,Read}` (`InventoryHandled` убран — спавн-на-землю тихий=`Granted`). Резолв игрока — переиспользуем `PlayerIdentityResolver` (ключ `PlayerName`→site `user_id`, null=fail-closed); broadcast/targeted единообразны через `mail_claims`. `GetMailAsync` **read-only** — джоин `mail`×`mail_claims`, стейт выводится, чтение не мутирует. Claimed-before-grant = unique-insert `mail_claims` до выдачи (`DuplicateKey`⇒`AlreadyClaimed`, зеркало DailyRewards). items→`ResolveStack`-паттерн (тип item/block из вложения, attr пусто⇒plain / непусто⇒base64 `TreeAttribute.FromBytes`+`MergeTree`, `RemoveTransitionState`, `TryGiveItemstack`→`SpawnItemEntity`); coins→сырой `$inc donate_wallets` воспроизводящий upsert vsservice `AddCoinsToWallet` (`$setOnInsert _id/created_at/version:1/player_name`) + аудит `donate_transactions`. Частичная выдача best-effort (мёртвый код скип+лог, не валит claim); `Unavailable` только если игрок не резолвится. **Откинуто на 01: `ItemAttachment` дополняется полем `type` (item/block)** — `ResolveStack` не угадывает namespace; 02 эмитит `type="item"`, 04 валидирует `type in {item,block}`.
- [Сериализация `ItemStack.Attributes`→base64 (research)](issues/07-attr-serialization-research.md): write=`stack.Attributes.ToBytes(BinaryWriter)`→base64, read=`Attributes.FromBytes(BinaryReader)` overwrite (не `MergeTree`). Снимок 1 предмета = **Code (namespaced) + ItemClass (item/block) + StackSize + attr-base64** (пусто если `Attributes.Count==0`); НИКОГДА `ItemStack.Id` (runtime-id). Стрип `transitionstate` (вкл. `contents["0"]` контейнера) обязателен; `temperature` прецеденты НЕ стрипают → решение за тикетом 09. Go — **чистый транспорт** base64-строки (не парсит; формат .NET `BinaryReader`). Цитата-метод: `NatsKitsSystem.GiveKitItemsToPlayer` (`Systems/Kit/KitModSystem.cs` L360). Findings: `research/07-attr-serialization-findings.md`, ветка `research/attr-serialization`.
- [Заливка иконок в MinIO из C# (research)](issues/08-minio-csharp-upload-research.md): NuGet `Minio` 7.x, `MinioClient().WithEndpoint().WithCredentials().WithSSL().Build()`+`PutObjectAsync`. Env vsservice реально = `MINIO_ENDPOINT`(host:port)/`MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY`/`MINIO_USE_SSL` (**не `*_FILE`** — docs устарели); VintageAPI зеркалит как `VINTAGEAPI_MINIO_*`. Findings: `research/08-minio-csharp-upload-findings.md`, ветка `research/minio-csharp-upload`.
- [Kit-storage: контракт коллекции `kits`](issues/09-kit-storage-contract.md): единый источник кит-определений, зеркало DailyRewards (игра — владелец контента Mongo-direct, vsservice — читатель+писатель метаданных). Ключ upsert=**`code`** (слаг из игры, unique; `ShopItem.Code`==`kits.code`, нового поля нет); `title`=отображаемое имя, правит сайт. Схема `kits{_id,code,title,items[]KitItemDoc,created_at,updated_at}`, `KitItemDoc{game_code(полный namespaced Code — и восстановление стека, и иконка),type item/block,quantity,attr_snapshot base64,image_url CDN}`. **Два писателя, непересекающиеся `$set`**: захват C# `upsert {$set:{items,updated_at},$setOnInsert:{code,title:"",created_at}}` (title не затирается перезахватом); rename Go `$set:{title,updated_at}` **без upsert** (`NotFound` если не захвачен, Go контент/insert никогда). Read-модель = **новый домен `internal/kitdef/`** (владеет `kits`, read-порт `GetKit(code)` для mail-11; старый `internal/kit` можно удалить целиком — отдельная задача). proto **`kitdef/v1`** `KitDefService`: `ListKits`(GET `/v1/kitdefs`, **без attr_snapshot по проводу**, для broadcast-выбора 04/11)+`RenameKit`(POST `/v1/kitdefs/{code}:rename`, `NotFound` если не захвачен), один scope **`kit:edit`**. bson snake_case заморожен (кросс-язык C#↔Go, `attr_snapshot`=opaque base64 обе стороны). **`temperature` — СТРИПАТЬ** (Q7): при выдаче at-claim вместе с `transitionstate` (снимок в `kits` честный), т.к. `temperatureLastUpdate` календарно-относителен и протухает у долгоживущего шаблона. ⚠ **Расширяет strip-набор тикета 05** на `temperature` для ВСЕХ выдач at-claim.
- [Разворот кит-мейла at-compose](issues/11-kit-mail-expansion.md): кит НИКОГДА не примитив вложения — mail-internal `kitExpander.expand(kitID)→[]Attachment` читает `kits` через consumer-порт `KitReader.GetKit(code)` (зеркало `MailComposer` 02, ацикл), проброс `game_code`+`type`+`quantity`+`attr_snapshot` как есть (mail не парсит; strip `temperature`/`transitionstate` at-claim, не тут; `image_url` не едет). Порт `MailComposer`+=`ComposeKitMail(ctx,recipientPlayerID,kitID,title,body,purchaseID)` — donate шлёт только `kitID`=`item.Code` (=`kits.code`, нового поля нет; `Code` двузначен по `Type`). `Buy()` для `type=kit` зовёт `ComposeKitMail` **вместо** ручного `MarkIssued` (данные теперь есть), штамп `IssuedAt`+`IssuedBy="system:mail"` как item(02); `MarkIssued` остаётся deprecated (recovery/reconcile). Кит отсутствует/пуст at-compose → `expand` fail-loud (`NotFound`/`FailedPrecondition`, пустой≡отсутствующий, НЕ claimless-письмо), compose-шаг падает, purchase есть но не штампован → reconcile (idempotent по `purchaseID`, механизм=fog 02). Админ-broadcast кита = **отдельный RPC** `ComposeKitMail` в `MailService` (`ComposeMail` из 04 не трогаем — oneof-с-repeated неуклюж), `recipient oneof{user_id|broadcast}`+`kit_id`+title/body+expires_at+idempotency_key, route `POST /v1/mail:compose-kit`, scope `mail:compose`, тот же `kitExpander`. **Правит тикет 04** (аддитивно: +метод+scope+route).
- [Игровая команда захвата кита](issues/10-capture-command.md): захват = **утилити-блок для админов** (`KitCaptureBlock`+`BlockEntityKitCapture`, universal), НЕ команда над сундуком. Правый клик → privilege `controlserver` (не команда) → vslibgui-GUI: 64-слот `InventoryGeneric` (персист в chunk-данных) + textbox(`code`-слаг) + Save. Зеркало DailyRewards: lhgui владеет блоком+GUI+транспортом, VintageAPI реализует backend-сиам **`IKitCaptureBackend`** (Mongo+MinIO, `Secrets.MongoUrl`, `SetBackend`). Транспорт Save = **выделенный канал `lhgui-kitcapture`** (паттерн DailyRewards, не блок-энтити-пакеты), пакет `{blockPos, code, KitIconPacket[]{slotIndex,png}}`. Снимок предмета — **сервер-authoritative** по инвентарю блока (переиспользует `NatsKitsSystem.OnKitCreate` L496-503): `game_code`(namespaced `Collectible.Code`)+`type`(ItemClass явно)+`quantity`+`attr_snapshot`(base64 чистый `ToBytes()`, НЕ `GetBuffer()`; пусто при Count==0; НЕ persist `ItemStack.Id`; strip на claim, не тут). Иконки: **клиент рендерит PNG** (08: offscreen FBO→`RenderItemstackToGui`→`GrabScreenshot(withAlpha)`→ARGB→PNG), сервер матчит по `slotIndex`, upload в MinIO → `image_url`. Запись: **upsert контента ПЕРВЫМ** (09-контракт `$set:{items,updated_at}`+`$setOnInsert:{code,title:"",created_at}`, upsert), **потом** best-effort иконки+`$set image_url` по слоту, **без отката** (11 не читает `image_url`; провал иконки=`""`, чинится перезахватом). Бакет **новый `kit-icons`** (bootstrap в `internal/media/fx.go`, vsservice ставит public; VintageAPI только `PutObjectAsync` `VINTAGEAPI_MINIO_*`), `image_url`=`<CDN_host>/kit-icons/<uuidv7>.png`.

- Агрегация HUD-бейджа (непрочит. почта + незабранные награды) — **решено в тикете 06**: простая сумма, один брасс-бейдж (`ServerMenuHudGui.Badge` слушает оба `Model`). Раздельные бейджи/цвета не нужны (YAGNI).
